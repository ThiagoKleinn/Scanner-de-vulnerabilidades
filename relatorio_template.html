Ferramenta: Scanner de Vulnerabilidades Web + Análise Estática

1. Descrição da ferramenta

Ferramenta própria em Python composta por três módulos independentes: um scanner de SQL Injection, um scanner de XSS (refletido e armazenado) e um analisador de código estático que combina Bandit, Semgrep e regras próprias. Os dois primeiros testam o DVWA (Damn Vulnerable Web Application) em ambiente controlado via Docker; o terceiro analisa um código-fonte de exemplo com falhas propositais.

2. Metodologia

SQL Injection: login automatizado via requests, envio de payloads classificados (baseados em erro, booleanos e baseados em tempo) e comparação de respostas contra um baseline. XSS: automação via Selenium, confirmando execução real de JavaScript no navegador (não apenas reflexo no HTML) e persistência para o caso armazenado. Análise estática: execução do Bandit e do Semgrep sobre o código-alvo, mais três regras próprias (segredo hardcoded, comando de shell concatenado, uso de eval/exec), com mesclagem dos achados por arquivo e linha.

4. Impacto e consequências

SQL Injection permite ler, alterar ou apagar dados do banco sem autorização, incluindo contornar autenticação. XSS permite executar código no navegador de outras vítimas — o armazenado é mais grave por não depender de a vítima clicar em nada. As falhas de código (segredos expostos, eval/exec, deserialização insegura) permitem, respectivamente, acesso indevido a serviços externos, execução de código arbitrário a partir de entrada do usuário e execução de código via objetos manipulados.

5. Medidas de mitigação

  • SQL Injection: usar queries parametrizadas/prepared statements, nunca concatenar entrada do usuário na query.
  • XSS: escapar toda saída renderizada no HTML e adotar uma Content-Security-Policy.
  • Segredos no código: mover para variáveis de ambiente/secret manager e rodar scanner de segredos no CI.
  • eval/exec: substituir por alternativas seguras como ast.literal_eval quando possível.
  • Deserialização insegura: evitar pickle para dados não confiáveis; usar JSON.

6. Conclusão

A ferramenta identificou com sucesso {{ sqli|length + xss|length + estatica|length }} achados distribuídos entre os três tipos de falha exigidos, com evidências reproduzíveis (requisições, comparações de resposta e screenshots) e lógica de detecção própria em cada módulo, reduzindo a dependência de ferramentas prontas e de falsos positivos.
